(4) 회원 가입 서비스
[회원 가입]
public MemberResponse create (MemberRequest memberRequest) {
   Member member = Member.builder()
                         .name(memberRequest.getName())
                         .email(memberRequest.getEmail())
                         .age(memberRequest.getAge())
                         .enabled(true).build();
   memberRepository.save(member);
   return mapToMemberResponse(member);
}

[회원 엔티티 객체 -> 회원 응답 객체 변환]
private MemberResponse mapToMemberResponse(Member member) {
   return MemberResponse.builder()
                .id(member.getId())
                .name(member.getName())
                .email(member.getEmail())
                .age(member.getAge())
                .build();
}

[복수 회원 일괄 생성]
@Transactional   <--[ref] "일괄 처리"를 하기 위해 붙이는 어노테이션
public List<MemberResponse> createBatch(List<MemberRequest> memberRequests) {
   List<MemberResponse> memberResponseList = memberRequests.stream().map(this::create).toList();    --[ref] memberRequests 에서 stream() 으로 memberRequest 를 하나씩 받아 map() 을 통해 create 함수(위에 정의된 사용자함수)와 매핑하여 하나씩 처리하고 return 된 memberResponse 를 toList() 로 반환함
   return memberResponseList;
}


**[중요][일괄처리]
@Transactional 을 붙이지 않은 경우 처리: 메서드 처리 중 에러(email 중복)가 발생하면, 그 이전에 정상 처리된 부분까지만 저장되고 에러 발생한 지점에서 멈춤.
@Transactional 을 붙인 경우 처리: 메서드 처리 중 에러(email 중복)가 발생하면, 그 이전에 정상 처리된 모든 트랜젝션이 함께 rollback 처리됨. (all or nothing)

@Transactional 어노테이션: "일괄 처리" 어노테이션으로 메서드 또는 클래스 에 붙일 수 있음
  - 메서드: 메서드에서의 처리를 하나의 Transaction 일괄처리로 묶어서 처리함. 
            즉, 중간에 에러가 발생하는 경우는 앞에서 처리된 모든 트랜젝션이 전부 함께 rollback 처리됨.
  - 클래스: 클래스 내에 정의된 모든 메서드는 @Transactional (일괄처리) 하게 처리됨
